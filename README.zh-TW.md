# 風與潮 Wind & Tide

[English](README.md) · **繁體中文**

用 Three.js 與 React Three Fiber 打造的台灣海峽即時數位孿生。

打開就是海峽：Sentinel-2 衛星影像鋪滿整座島嶼，依今天浪況預報起伏的 FFT 海面，沿東岸奔流的黑潮，
以及 513 座隨著此刻海峽真實風向轉動的離岸風機。

**線上體驗：https://m24927605.github.io/taiwan-wind-power/app/**

[![風與潮：從即時網站逐格錄製的兩分鐘影片](docs/teaser.webp)](https://m24927605.github.io/taiwan-wind-power/)

**[English](https://m24927605.github.io/taiwan-wind-power/#en)**

每個鏡頭都是網站本身的即時渲染，時間取自預報區間內的真實日期與時刻：清晨的波紋、縮時日落、
依真實月相沉入海峽的月亮。影片在虛擬時鐘上逐格擷取，因此不受電腦效能影響，維持 60 fps。
旁白由 Gemini TTS 生成。

```bash
npm install
npm run dev            # http://localhost:5199
npm run build
npm test               # 單元測試（Vitest）；CI 每次部署前都會執行
```

每次推送到 `main` 都會自動建置，並發佈到 `gh-pages` 分支的 `app/` 資料夾（`.github/workflows/pages.yml`）；
影片頁位於該分支的根目錄。

氣象資料經由一個小型 Cloudflare Worker（`worker/`）取得：它依排程每小時抓取 Open-Meteo，其餘時段輪流抓取
氣象署的浮標與潮位站資料，存進 KV（每 10 分鐘一次的排程每次只做其中一份，以維持在免費方案的 CPU 額度內），所有訪客讀的都是這份存好的資料，所以對外請求次數固定、與流量無關，抓取失敗時也會保留上一份
好資料；氣象署授權碼只存在那裡。頁面開著時，應用程式每 10 分鐘重新讀取一次。應用程式從 `VITE_WEATHER_SERVICE`
（`.env.production`）讀取 Worker 的網址；未設定或連不上時，應用程式會自己抓取 Open-Meteo，並顯示未經校正的模式值。
數據面板底部列出每個資料來源與最新一筆資料的時間；更新逾時（模式超過 2 小時、實測超過 3 小時）或沒有取得實測值時，
會以紅字標示。

```bash
npx wrangler secret put CWA_API_KEY --config worker/wrangler.jsonc   # 只需一次；氣象署開放資料授權碼
npx wrangler deploy --config worker/wrangler.jsonc
```

使用 `wrangler dev` 時，把授權碼放在 `worker/.dev.vars`（`CWA_API_KEY=...`，已被 git 忽略）。

| 月面 | Solar System Scope 2k 月球貼圖（依 NASA LRO 影像） | 由 `scripts/build-moon.ts` 烘焙成 1024 × 512 的反照率貼圖，貼在月球正面 |

時間軸可拖曳整個 96 小時區間，播放鍵會以縮時方式播放。風機出力來自三次方功率曲線（切入 3 m/s、
額定 12 m/s），再依各風場的額定容量縮放。強風時依各風場的機型而定：Vestas V174 的風場從 25 m/s
起逐步降載、31 m/s 停機（Vestas 的高風速運轉）；其餘風場在 25 m/s 停機，Siemens Gamesa 的高風速
運轉是選配，台電實測出力顯示這些風場沒有採用。風速降回 22 m/s 以下才重新啟動。各風場實際的控制
設定並未公開。風場的機組數與容量依公開資料；風機座標是
近似的陣列排列，介面上也有註明。

## 互動

- 點選風機會飛到它旁邊。機艙以動畫剖面切開，標示主軸承、齒輪箱、發電機、變流器與偏航系統。
  點選標籤會開啟說明卡片，附即時讀數（主軸轉速、齒輪箱輸出轉速、發電機出力、變流器負載率、
  機艙朝向）。側邊面板顯示即時風速、轉速、出力與功率曲線。
- 風場依陣列方向畫出外框，並標示機組數與容量，在風機只剩小點的全景也看得清楚。標籤從各風場的
  西側角落伸向開闊海峽；互相重疊時，大風場優先。點選標籤或外框內任一處會飛到該風場上空；到了
  之後，點選又會改為選取單一風機。鏡頭進入風機之間時，外框會淡出。
- 鏡頭離開全島視角後，畫面上方會出現「回到台灣全景」按鈕，點一下即可飛回。全島視角北方朝上，從南方傾斜 10° 俯瞰，依螢幕比例退到資料範圍允許的最遠處。
- 畫面上的一切都是有資料的區域：資料範圍（東經 116.6°–125°、北緯 21.4°–25.8°）寬到足以在橫向螢幕上北方朝上看到
  全島，任何鏡頭位置都不會看到範圍外的地面（`scene/camera.ts` 的 `viewInsideDomain`）；拖曳、縮放或滾輪超出時
  會彈回。鏡頭在 3 公里以下時，視野可以延伸到大氣霧化的地平線，但鏡頭本身須在範圍內 30 公里。程式飛行會繞著
  目標點移動，俯仰角跟著縮放進度變化，所以飛行途中也不會超出範圍。
- `M` 量測大圓距離與方位角，量測點會吸附到風機。
- `E` 切換工程模式：診斷渲染加上即時渲染統計。只在開發環境提供，工具列按鈕亦同。
- `Space` 播放或暫停縮時，`R` 回到全景，`Esc` 取消選取。

## 架構

```
scripts/            離線資產流程（Node，執行一次）
  tiles.ts            Web Mercator 圖磚拼接 -> 重新取樣到場景網格
  build-elevation.ts  Terrarium 圖磚 -> Terrarium 編碼 PNG 高程網格（海底地形）
  build-terrain.ts    z11 Terrarium -> 陸地網格 -> meshopt 簡化 -> 量化 GLB
  build-imagery.ts    Sentinel-2 cloudless + z11 法線 -> WebP 貼圖
  build-tidal-flats.ts Sentinel-2 影像 + 潮位站 -> 潮灘高程 PNG（需要 CWA_API_KEY）
  harmonics.ts        含交點修正的潮汐調和分析
  build-turbine.ts    程序化風機 -> meshopt LOD -> 量化、meshopt 壓縮的 GLB
  snapshot-weather.ts 一週內的 Open-Meteo 回應 -> 給沙盒環境用的內建備援資料
  build-artifact.ts   artifact 模式建置 -> 給 claude.ai 的單一內嵌頁面 + .gltf 模型
src/
  geo/              範圍投影（經緯度 <-> 公里）、太陽位置、大地測量
  data/             高程載入、Open-Meteo 請求與氣象客戶端、風場排列
  scene/            R3F 場景：天空、地形、黑潮 GPGPU、風場、主角風機
    ocean/            FFT 波浪模擬與海面著色
    camera.ts         命令式相機 API（飛到風機、風場、全景）
    Layer.tsx         每個需載入資產的場景部分各自的錯誤 + Suspense 邊界
    farmAreas.ts      由排列推導的風場外框，以及解析式風場點選
    turbine/          GLB 存取、各風場動態、instanced LOD、剖面主角風機
  ui/               HUD、時間軸、工具列、風機面板、工程模式疊層
  state.ts          zustand store：階段、資料、場景時間、工具、統計
worker/             氣象服務（Cloudflare Worker）：每小時抓 Open-Meteo、每 10 分鐘抓氣象署浮標，存進 KV
```

每一幀的模擬狀態，例如各風場的轉子角度、偏航與風速，存放在一般的型別陣列（`farmDynamics`）中，
著色器以 uniform 陣列讀取。React 只保存以 UI 頻率變動的狀態。渲染迴圈不配置記憶體。

## 效能筆記

在 Apple M1 的無頭 Chrome、1440 × 800、DPR 1 下量測：在風機旁 60 fps，全景且本島上空有雲時約
53 fps，其餘交給自適應品質。體積雲、逐像素大氣與海面佔了每幀的大部分成本。

**513 座風機只需四次 draw call。** 每座風機都是一個 instance。每個 LOD 層級有兩個
`InstancedMesh`：機身與轉子。偏航與轉子旋轉在頂點著色器中由各風場的 uniform 陣列與每個 instance
的相位計算，因此讓風機動起來不需要任何 CPU 矩陣運算。每三幀 CPU 會依視錐（球體測試）與距離重新分組：

| 分組 | 範圍 | 幾何 |
| --- | --- | --- |
| LOD0 | < 7 km | 完整網格，約 1.6 萬三角形 |
| LOD1 | 7–70 km | meshoptimizer 簡化，約 6 千三角形 |
| LOD2 | > 70 km 或被剔除 | 一個點（夜間為航空警示燈） |

在全景中，513 座風機全部合併成一次 `Points` 繪製。

**海上是真實尺寸，從高空也看得見。** 鏡頭高度在 1 公里以下時，風機以真實尺寸繪製，風場維持真實的
六到八倍葉輪直徑間距；再往上則依高度的對數逐漸放大，到 40 公里時為 2.5 倍，否則真實尺寸的風機在地圖上
會看不見。每座風場依自己機型的葉輪直徑縮放共用的模型，從 136 m（台電一期）到 222 m（海龍、大彰化西北）。
instancing、點選、航空警示燈、主角風機與其陰影範圍、相機飛行，都使用同一套各風場的尺寸。

**資產流程。** 風機依海峽中的中速機型（V164/V174 系列）程序化建模：四腳套管式基礎、黃色轉接段與
附欄杆的平台、靠船設施與吊臂、帶法蘭的三段式塔架、頂部有冷卻器與直升機吊掛平台的長機艙，以及
81 m 的預彎葉片。每個頂點都帶有反照率、表面屬性（粗糙度、金屬度、風化程度），以及在建置時用
three-mesh-bvh 光線追蹤出的環境光遮蔽。接著 glTF-Transform 套用 `reorder`、`quantize`
（KHR_mesh_quantization）與 `EXT_meshopt_compression`：六個網格含兩層 LOD 共 243 KB。載入時再把
反量化轉換烘回浮點幾何，以便 instancing。

**不用貼圖的塗裝鋼材。** 風機材質是在 `onBeforeCompile` 中修補的 MeshPhysicalMaterial
（`turbine/weathering.ts`）：粗糙度、金屬度與遮蔽來自頂點，塗裝上的亮面 clearcoat 沿塔身映出天空與
地平線，這正是塗裝鋼材看起來像鋼材的關鍵。磨損加在模型空間，因此機艙偏航、轉子旋轉時都不會滑動：
色調變化、垂直面上的雨痕、沿黃色鋼材流下的鏽痕、浪花區的藻類與鹽漬，以及機艙面板之間的接縫。

**FFT 海面。** 海面是 Tessendorf 海洋。雙峰波譜：即時風浪（JONSWAP 加 Hasselmann 方向分布）加上
即時湧浪（窄譜、長波峰），隨時間演化，並在片段著色器中以 radix-2 Stockham FFT 轉換到空間域。三層
cascade（512 m、97 m、17 m 的圖塊，在六倍基頻處交接）共用一張 768 × 256 圖集；兩張半浮點渲染目標
裝載八個打包的實數場（choppy 位移、高度、斜率與 Jacobian 的導數），因此模擬是 1 + 16 + 2 個 pass。
一次 resolve 寫出各 cascade 的位移給頂點著色器，以相機為中心的放射狀網格（環距與半徑成正比，眼睛
正下方約 10 m，一路延伸到範圍外）在與間距相符的 mip 上取樣位移。另一次 resolve 寫出帶 mipmap 的
（斜率、斜率²、泡沫）：mip 濾波保留了遠處平均後會消失的斜率變異，供 Beckmann 閃光使用；泡沫在海面
摺疊處注入並在數秒內衰減，所以白浪會留下尾跡。碎浪來自所有 cascade 合併後的 Jacobian。波浪以真實
尺寸繪製，和鏡頭靠近海面時的風機一致；在淺水區波浪會平息，不會爬上海岸。

**GPU 上的黑潮。** 粒子狀態（範圍 uv、年齡、壽命）在 `GPUComputationRenderer` 的 RGBA32F 渲染目標
之間來回交換。洋流場是一張 24 × 14 的 RG16F 貼圖，使用硬體雙線性濾波，並以 uniform 混合相鄰兩個
逐時資料。陸地遮罩取樣共用的高程貼圖。粒子以 instanced 條紋四邊形繪製，長度隨流速與相機距離變化，
在全景中讀起來像水流；鏡頭降到 12 公里以下時逐漸淡出，2 公里以下完全隱藏，因為在風機之間它們只會像
一道道劃過水面的白線。

**一張高程貼圖，多種用途。** 單一 R16F 貼圖同時提供海水深度著色、等深線、碎浪、平靜淺灘與粒子陸地遮罩。

**地形即資產。** 陸地以真實比例建模，沒有垂直誇大。網格從 2048² 的 z11 網格開始，只保留碰到陸地的
格子（176 萬三角形）。meshoptimizer 再以 25 m 的絕對誤差簡化（小於來源網格間距），平原塌縮成少數
大三角形，稜線則保留細節：113 萬三角形，量化並 meshopt 壓縮後 3.1 MB。海岸格子會向下傾斜到水面下的海底頂點；地形不繪製低於陸地 4 公尺抬升高度的部分，海岸線交給海面處理。著色來自 Sentinel-2 影像與
4096² 法線貼圖，並先除去影像中烘焙的上午 10:30 陽光，再套用場景的太陽。本島有自己約每像素 50 m 的
z12 影像，在其範圍邊緣淡入；手機與不支援 8192 貼圖的 GPU 則使用整體影像（東西方向約每像素 200 m）。夜間燈光不是手動
擺放的：它們來自影像中明亮、灰色且平坦的像素，也就是真實的都市紋理。

**物理大氣。** 天空採用 Hillaire（2020）模型，以公里為單位：穿透率與多重散射 LUT 只繪製一次，每幀
繪製兩張 sky-view LUT，一張從相機出發（天穹，從軌道高度看也正確），一張從海面出發（照亮地面並被地面
反射的天空）。所有材質都以場景輻射亮度著色，並沿視線積分相同的散射，套用逐像素的大氣透視，因此山脊
會淡入一層層藍色，地平線溶入霧氣，全景是透過 100 km 的空氣往下看。three.js 的太陽光顏色取自 CPU 端
的穿透率，以天空平均輻射亮度測光的曝光（部分適應，讓黃昏維持黃昏）再送入 ACES 色調映射。航海暮光
之後，位於真實位置與相位的月亮成為整條管線的主光源。月亮是真實的月面照片，月面北方依台灣所見指向
天球北極，以 Lommel-Seeliger 反射模型依真實月相照亮，暗面有微弱的地照。星空也是真實的：耶魯亮星星表中
6 等以內的每一顆星，依地方恆星時旋轉，大小依星等、顏色依 B−V 色指數，接近地平線時以同一套穿透率變暗；
月亮高掛時暗星會被洗掉。夜晚不會完全適應黑暗：月光照度維持在讓月夜天空比航海暮光更暗的程度，月亮與
星星則以固定的顯示亮度呈現。

**體積雲。** 雲只出現在向日葵 9 號看到的位置：`data/satellite.ts` 用圖層本身的色階
把 Band 13 紅外線換算回亮溫，明顯比晴空海面冷的地方就是雲（陸地則以海面溫度依氣溫遞減率修正，並對
被太陽曬熱的山坡放寬門檻）；雲頂越冷長得越高，最冷的成為卷雲。白天再以 Band 3 可見光補上反射遠高於
海面與陸地的低雲。相鄰的逐時掃描交叉淡化，所以縮時能看到真實天氣的移動。沒有其他來源的雲：預報時段，以及
連不上 GIBS 時，天空都是晴朗的。它們在 0.9–2.9 km 的平坦雲層中做光線
步進（以 Worley 細節侵蝕的 Perlin-Worley 形狀，載入時在 GPU 生成），加上多階散射與 powder 變暗，
作為後處理 pass，每條光線在深度緩衝處停止，所以山脈能穿出雲層。每個 2x2 區塊每幀只步進一個像素並
降低解析度，其餘由重投影補上；joint bilateral 上採樣保持輪廓銳利，並從雲隙朝太陽追蹤耶穌光。地形與
海面會接收雲影，海面反射每四幀更新一次的多雲環境，從全景看時雲會變薄，讓地圖保持可讀。

**照亮風機。** 那片多雲的海平面天空會在主光源移動或曝光改變時濾成 PMREM 環境貼圖，讓亮面塗裝映出
天空與海。被選取的風機還會從緊貼它的陰影視錐投下柔和的日光陰影。

**音景。** Web Audio，預設關閉，由觀看者自行開啟（`audio/engine.ts`）。海浪與海風的錄音隨相機遠離
水面而淡出、變悶，並隨即時海況增強；風聲本身是帶通濾波的粉紅雜訊，音量、音色與陣風都跟著輪轂高度
風速；最近的轉子則是以葉片通過頻率（即時轉速的三倍）調幅的雜訊，依其位置做左右聲像，底下再疊上近距離
錄下的機械聲。白天靠近水面時偶爾有海鷗叫聲，底下鋪著一首 CC BY 配樂，相機飛行與選取也有合成音效。
五個聲道（主音量、音樂、環境音、白噪音、音效）從工具列調整，並依瀏覽器記憶；分頁隱藏時音訊會暫停。

**兩種語言。** 繁體中文與英文，從工具列切換並依瀏覽器記憶，預設跟隨瀏覽器語言（`i18n.ts`）。英文
字串表的型別以中文表為準，缺少字串會讓建置失敗；日期、星期與方位會隨語言改變，文件標題與 `lang`
也一樣。

**錯誤隔離。** 場景中每個需要載入自身資產的部分都放在 `Layer` 裡：包著 Suspense 邊界的錯誤邊界。
檔案遺失或損壞只會影響那一層，不會拖垮整個 canvas。地形會逐步降級：沒有本島影像時改用整體影像。

**跨越 1000 倍縮放的深度精度。** 相機的近平面跟著高度變化，從機艙旁的 4 m 到軌道高度的 5 km。
這樣就不需要對數深度緩衝，也省下隨之而來的著色器成本。

**自適應品質。** `PerformanceMonitor` 在畫格耗時過長時以 0.25 為單位降低 DPR，有餘裕時再調回。
DPR 超過 1.5 倍時停用 composer 中的 MSAA，因為成本大於效果。觸控裝置一開始就使用較少粒子。

**資料預算。** Open-Meteo 把多點請求中的每個座標都算作一次呼叫，並依 IP 限流（免費方案每分鐘 600 次、每天
10,000 次）。每次載入要求約 307 個座標：網格中的海上點（陸地上的 44 點海況模式沒有資料，不請求，改由相鄰點補值）、
各風場，以及用來校正風速的浮標。氣象服務每天替所有訪客發出 24 次這個請求，約 7,400 次呼叫。當應用程式
必須自己抓取 Open-Meteo 時，回應在 `localStorage` 中快取 30 分鐘，配合逐時更新的頻率，所以重新整理不需花費
任何呼叫額度。

### 值得知道的陷阱

- z11 的 Terrarium 圖磚沒有海底地形：海面一律是 0 m。陸地遮罩結合了 z11 與有海底地形的 z9。
- Open-Meteo 在海峽的 `wave_peak_period` 回傳 `null`。平均週期會換算成 JONSWAP 波譜的峰值週期
  （Tp ≈ Tm / 0.83）。
- 兩個 `onBeforeCompile` 材質若來源字串完全相同，會共用同一個編譯後的 program，轉子就會默默用機身的
  著色器渲染。請設定 `customProgramCacheKey`。
- 在 XZ 平面建立的平面四邊形從上方看時繞向會翻轉，除非雙面渲染，否則會被當作背面剔除。
- 在 React StrictMode 下，於 `useMemo` 建立、在 effect cleanup 中釋放的 GPU 資源會在第一次使用前就被
  銷毀。請在同一個 effect 中建立並釋放。

## 部署為 claude.ai artifact

```
npm run snapshot:weather   # 更新內建的 Open-Meteo 備援資料（涵蓋未來 7 天）
npm run build:artifact     # dist-artifact/artifact.html 以及模型、貼圖與資料
```

接著發布 `dist-artifact/artifact.html`，並把 `dist-artifact/` 中的其他檔案（`assets/` 與 `index.html`
除外）以相同路徑作為附屬檔案。artifact 主機只允許來自 Google Fonts 的樣式表，也只提供網頁檔案類型，
因此頁面會內嵌應用程式的 CSS 與 JS，artifact 模式的建置則把每個模型載入為由 `.glb` 無損重新封裝的
獨立 `.gltf`。所有資產網址都是相對路徑（`base: './'`）。若觀看者無法連上 Open-Meteo，應用程式會讀取
快照並標示它是快照，附上取得時間。

## Open Sea（`sea/index.html`）

一件位於海平面的姊妹作品：單一獨立 HTML 檔（three.js 來自 CDN，不需建置），從水面上幾公尺一路渲染
到雲層的開闊海峽。以靜態方式提供該資料夾（`python3 -m http.server -d sea`）後開啟即可。

- **天空**：Hillaire（2020）：穿透率、多重散射與 sky-view LUT，海洋邊界層的 Mie 霧氣，以及海面與雲
  的逐像素大氣透視。
- **雲**：在球殼中光線步進的積雲，以 Perlin-Worley 雜訊塑形並以 Worley 細節侵蝕（載入時在 GPU 生成），
  使用多階散射、雙瓣相位函數與 powder 變暗照明。每個 2x2 區塊每幀只步進一個像素，其餘由重投影補上；
  joint bilateral 上採樣讓地平線保持銳利。上方有被風梳理的卷雲，下方有雲影與耶穌光。
- **海**：來自雙峰波譜（風浪與湧浪）的三層完整 choppy 位移 FFT cascade，隨地球曲率延伸到地平線的
  以相機為中心放射狀網格，透過 mip 鏈保留斜率變異以得到經過濾波的閃光，以及在合併 Jacobian 摺疊處
  生成、在圖塊空間中衰減並留下尾跡的白浪。
- **時間**：海峽上空真實的日月位置。航海暮光之後，真實相位的月亮照亮整條管線；星星隨大氣消光淡入。
- **資料**：「套用即時海況與時間」會套用北緯 24.0°、東經 119.9° 的即時 Open-Meteo 風、風浪、湧浪與
  雲量。在那之前，頁面顯示典型的十月東北季風海況。
- **預算**：依量測到的畫格間隔自適應解析度；反射環境每四幀更新一次，bloom 以一半解析度執行。
